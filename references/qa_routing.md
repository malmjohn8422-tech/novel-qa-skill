# 问答路由

入库完成后,用户对已入库小说提问时,**按本文档决定"读哪些文件、读到什么程度"**。核心原则:**先读最小必要的索引/摘要,只在不够时才加载块全文**。

---

## 0. 前置检查(每次提问前 30 秒内完成)

### 0.1 哪本书?

先运行:

```
python <skill_dir>/scripts/search_novel.py books
```

列出 `./library/` 下的子目录和 `meta.json` 里的基本信息。

| 情况 | 行为 |
|---|---|
| 没有任何子目录 | 告诉用户"还没入库任何小说",建议先入库 |
| 只有 1 本 | 用那本,无需问 |
| 多本,问题里**提到了书名** | 锁定到那本 |
| 多本,问题里**提到了独有角色名/地名** | 查每本的 `次要角色.json` + `角色/*.md`,锁定到匹配的那本 |
| 多本,无法判断 | 用**最近入库的**(看 `meta.json` 的 `ingested_at`);一句话告知用户"按最近入库的《X》回答,如要换书请说明" |

### 0.2 Stage 进度?

跑 `python <skill_dir>/scripts/aggregate.py status {slug}`,看 Stage 2 产物是否齐全。

| 状态 | 可用功能 |
|---|---|
| 0+1+2 全完成 | 全部路由可用 |
| 0+1 完成,2 缺失 | 只能用 chunk summaries,**降级**(见 §4) |
| 0 完成,1 缺失 | 只能用 chunk 全文 + 章节索引;角色问答几乎不可用,告诉用户先跑 Stage 1 |

## 1. 问题分类

按问题里的**关键词信号**判别类型。一个问题命中多个信号时,**按下表从上到下优先级**判定。

| 优先级 | 信号关键词 | 类型 | 路由 |
|---|---|---|---|
| 1 | "原文"、"原话"、"逐字"、"引用一下" | 原文引用 | §2.7 |
| 2 | 章节号("第N章")或明确章节标题 | 章节情节 | §2.6 |
| 3 | 角色名 + "穿/戴/外貌/神态/动作/手里拿/说了什么"等具体词 | 角色细节 | §2.5(走具体细节路径) |
| 4 | 角色名 + "是谁/怎样的人/性格/经历/弧光" | 角色分析 | §2.4 |
| 5 | "世界观/设定/力量体系/科技/修炼/魔法/规则" | 世界观 | §2.2 |
| 6 | "主线/剧情走向/故事线/转折/发展/演进" | 故事线 | §2.3 |
| 7 | "整体/全书/总体/讲了什么/主题/风格/讲的是" | 整体概览 | §2.1 |
| 8 | 不含上述信号但提到具体事/场景词 | 具体细节 | §2.5 |
| 9 | 其他 | 按主体猜:有角色名走 §2.4,有动作词走 §2.5,实在没线索就当 §2.1 |

## 2. 路由决策细节

### 2.0 检索脚本优先

涉及块定位时,优先用 `scripts/search_novel.py`,不要直接让 main thread 大范围读文件:

```bash
# 摘要检索:返回命中块 + 短 snippet
python <skill_dir>/scripts/search_novel.py search {slug} "{关键词}" --source summary --limit 8

# 原文检索:只返回命中片段,不返回整块全文
python <skill_dir>/scripts/search_novel.py search {slug} "{关键词}" --source text --limit 8

# 章节定位
python <skill_dir>/scripts/search_novel.py chapter {slug} "{第N章/章节标题}" --limit 8

# 角色出场块定位
python <skill_dir>/scripts/search_novel.py character {slug} "{角色名}" --limit 8

# 模糊问题证据包
python <skill_dir>/scripts/search_novel.py evidence {slug} "{用户问题}" --limit 8
```

脚本结果只用于定位。真正回答前,按需要读取命中块的 summary 或全文,并在答案中保留块号引用。

对于分类不确定、关键词很多、或可能同时涉及角色/章节/细节的问题,先跑 `evidence`。它会返回 `likely_type`、`suggested_chunks`、summary/text 命中和角色/章节命中。`suggested_chunks` 会从章节、角色、摘要、原文命中中轮询取块,避免单一来源独占。再按证据包决定是否读取对应 summary 或全文。

### 2.1 整体概览(主题、风格、全书走向)

**首选源**:`概要.md`(已经是 ~1500 字浓缩,直接回答)

**如果用户问的够具体**(比如"主角的成长轨迹"、"反派的动机"),概要不够,**叠加**所有块摘要(`chunks/*.summary.json` 的 `summary` 字段拼起来,~20000 字),综合回答。

不要直接加载 chunks 全文——太重,无必要。

### 2.2 世界观 / 设定

**首选**:`世界观.md`(预生成 ~2000 字)

**如果用户问到了世界观.md 没覆盖的细节**(比如"灵气复苏后能源体系怎么运作"而 worldview.md 只提了"修炼体系"),叠加:
- 用 `search_novel.py search {slug} "{设定关键词}" --source summary --limit 8` 找命中块
- Read 命中块的 summary
- 不够再对同一关键词用 `--source text`,只 Read 最相关 1-3 个块全文

### 2.3 故事线 / 主线 / 转折

**首选**:`故事线.md`(预生成 ~2000 字,自带块号引用)

故事线.md 已经覆盖了主线节点。除非用户问的是"某次转折的细节"(那是 2.5 具体细节),否则直接用。

### 2.4 角色分析(性格、弧光、关系)

**步骤**:

1. 先运行 `search_novel.py character {slug} "{角色名}" --limit 8`,拿到出场块、可能的 `profile_path`、以及 `角色别名.json` 展开的 aliases
2. 角色名是否在 `角色/` 目录有 md 档案?
   - **是(主要角色)**:Read `角色/{name}.md`(已有 200 字速写 + frontmatter 含出场块号)
   - **否**:查 `次要角色.json`,拿到出场块号
3. 根据问题深度决定要不要加载更多
   - 速写够答 → 答完就好
   - 用户问得很细(比如"她为什么对主角态度变化") → Read 该角色出场块的 summary,综合回答
   - 还不够 → Read 这些块的全文(`chunks/NNN.txt`)
4. 答案必带块号

### 2.5 具体细节(衣着、神态、对话、场景)

**关键词搜索路径**:

1. 从问题里抽出**关键词**(角色名 + 动作/物品/场景词)
2. 用 `search_novel.py search {slug} "{关键词}" --source summary --limit 8`,找命中块
   - 如果命中块 ≤ 3 → Read 这些块的全文
   - 命中块 4-10 → Read 这些块的 summary,再选最相关 2-3 个 Read 全文
   - 命中块 > 10 → 用户问的可能是泛泛话题,提示"涉及多块,请问具体哪个场景"或直接给出代表性几块
3. 若 summary 里找不到关键词,但用户确定原文有 → 退到 §2.7 走原文搜索

### 2.6 章节情节

1. 运行 `search_novel.py chapter {slug} "{章节号/标题}" --limit 8`,根据脚本返回定位块号
2. 如脚本没有命中,再 Read `章节索引.md` 人工判断
3. Read 对应块(单块或多块)的 summary 或全文,看问题深度
4. 多章节连续问的,合并所有相关块

### 2.7 原文逐字引用

1. 从问题里抽**最具特征的几个字**(对话片段、人名+动作、独特物品名)
2. 用 `search_novel.py search {slug} "{关键词}" --source text --limit 8` 搜原文短片段(不走 summary)
3. Read 最相关的 1-3 个命中块全文,确认 byte-exact 引用
4. 命中后输出原文片段 + 块号

## 3. 多步检索

如果第一步加载的源**信息不够答**(比如概要里只说"主角和庄颜结婚",但用户问"婚礼是什么样的"),不要硬答,**继续下钻**:

```
概要 / 高级文档不够
    ↓
search_novel.py 搜 summary,拿命中块和 snippet
    ↓
仍不够 → search_novel.py 搜 text,再读命中块全文
    ↓
仍不够 → 换关键词重搜 text
    ↓
确定原文没有 → 坦白说"原文未涉及"
```

**每往下走一层,context 消耗显著增加**。能上一层解决就别下钻。

如果 `summary.json` 里包含可选 `keywords`,检索脚本会自动纳入关键词字段;旧库没有 `keywords` 不影响使用。

## 4. 降级:Stage 2 未完成

如果 `aggregate.py status` 显示概要/世界观/故事线 都没生成,但 `chunks/*.summary.json` 齐全:

| 问题类型 | 降级方案 |
|---|---|
| 整体概览 | 所有 summary 拼接 → 即时综合 |
| 世界观 | 同上,在 summary 里扫"设定/规则/能力"等关键词,提取相关段 |
| 故事线 | 按块号顺序读所有 summary 的 `key_events` 字段,串起来 |
| 角色分析 | 跨块扫 `characters` 字段,统计出现块号,Read 这些块的 summary 综合 |
| 章节情节 | 用 `search_novel.py chapter`;没有命中再读 `章节索引.md` 或 `chunks/*.meta.json` |
| 具体细节 | 同标准流程 |
| 原文引用 | 同标准流程 |

回答开头加一句"⚠ 注:本书 Stage 2 高级文档未生成,以下基于块摘要即时综合"以提醒用户。

## 5. 找不到信息的处理

如果走完整条决策树,确认原文没覆盖用户问的:

**正确做法**:坦白说

> 关于 X,原文未涉及 / 入库内容未明确说明。

或

> 在已入库的 N 块中没有找到这个细节。可能是:① 漏到了未识别的块;② 原文本身没写。建议确认。

**错误做法**:

- ❌ 编造细节"想必应该是……"
- ❌ 引用错误块号
- ❌ 把别处的内容套到这里

---

## 6. 常见错误模式

| 反例 | 正例 |
|---|---|
| 一上来读所有块全文 | 先读对应高级文档 / summary |
| 答案不带块号 | 每个事实后 `[块 N]` |
| 用户问角色分析,直接 grep 全文 | 先用 `search_novel.py character`,再查 `角色/{name}.md` |
| 模糊问题直接读很多文件 | 先用 `search_novel.py evidence` 生成证据包 |
| 多本书并存时不告诉用户用了哪本 | 明确说"基于《X》" |
| 答完之后又额外加"以上为推测" | 该说就说,不要在末尾自我否定 |
