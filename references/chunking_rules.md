# 切块规则

`scripts/split_novel.py` 的工作细节。Stage 0 入库时如遇异常情况、需要解释切块结果给用户、或需要调整参数,查这份文档。

---

## 1. 算法主线

```
1. 读全文,扫每一行,识别所有章节标题位置
2. 按章节切成"原始章节块"列表 [(标题, 内容), ...]
3. 维护一个"缓冲区",依次扫每章:
   a) 当前章字数 > 15000        → flush 缓冲区, 然后单独切分这一章
                                  (切出的最后一段进缓冲区,等下一章合并)
   b) 缓冲区字数 + 当前章 ≤ 15000 → 当前章加入缓冲区
   c) 否则                       → flush 缓冲区, 当前章入新缓冲区
4. 收尾:flush 剩余缓冲区
```

字数 = 非空白字符数(空格/制表/换行/全角空格不算)。

---

## 2. 章节识别正则

`is_chapter_heading()` 识别下列行作为章节标题(行需 strip,长度 ≤ 60):

| 模式 | 例子 |
|---|---|
| `第N章/回/节/话/卷/篇` | `第一章`, `第3回 长安城`, `第二十七节:夜袭` |
| 序章类 | `序章`, `序幕`, `楔子`, `引子`, `尾声`, `终章`, `前言`, `后记`, `番外`, `外传` |
| 卷标 | `卷一`, `卷二:风起`, `卷三十` |
| 英文 | `Chapter 5`, `Chapter 12: ...` |

N 可以是阿拉伯数字、中文数字(零一二三四五六七八九十百千万两〇)或混合。

还支持网文常见的短标题紧贴形式,如 `第三章我醒了`、`第12章新的开始`。这类宽松识别只在整行较短时启用。

**注意:** 标题行长度上限为 60,紧贴形式上限更短。这避免把 `他第三章节地说道...` 之类的正文当成标题。

---

## 3. 超长章拆分:边界优先级

切分超过 15000 字的章时,在 [10000, 15000] 字范围内找最佳切分点:

| 优先级 | 边界类型 | 例 |
|---|---|---|
| 1(最高) | 场景符号行 | `★★★` `* * *` `---` `═══` `——————` |
| 2 | 三星号行 | `* * *`(单独成行,星号间有空格) |
| 3 | 多空行 | 连续 ≥3 个换行 |
| 4 | 段落空行 | 连续 2 个换行 |
| 5(最低) | 句末标点 | `。！？…` 或闭合引号 `」』""` |

**每级在范围内取最晚出现的位置**,让块尽量接近 15000 字(避免切完后剩下尾巴太小)。

只在所有级都没匹配时才硬切在 15000 字处(极罕见,意味着上万字没有任何标点)。

## 4. 异常情况

### 4.1 没有章节标记
回退到"全文按字数切",仍用上面的边界优先级。`source` 字段标 `"no_chapter"`。

### 4.2 超长章节(>15000)
按上面的优先级在章内切。`source` 标 `"chapter_split"`,`chapters` 字段会带 `(第i/n段)` 后缀。
**最后一段会暂存到缓冲区**,让后续短章有机会合并进来。

### 4.3 短章 + 短章 + 超长章 = 加起来超上限
算法会先 flush 短章组合(可能只有 8000 字),然后处理超长章。
小块(< 10000)是可以接受的,**章节完整性优先**。

### 4.4 末尾小尾巴
如果最后一个块只有几千字,允许。这是因为章节边界在前,小尾巴单独成块好过往前合并破坏整体结构。

### 4.5 单段超过 15000 字
极罕见(整段无标点)。降级到"句末标点"切分。若连句末标点都找不到,硬切在 15000 字处。

## 5. 输出文件

### 5.1 `library/{书名}/chunks/NNN.txt`
块正文。原文 byte-exact,**不做任何修改**(包括空格、换行、错别字)。

### 5.2 `library/{书名}/chunks/NNN.meta.json`

| 字段 | 类型 | 说明 |
|---|---|---|
| `idx` | int | 1-based 块号 |
| `chars` | int | 字数(非空白) |
| `source` | str | `complete_chapters` 完整章合并 / `chapter_split` 超长章拆出 / `no_chapter` 无章节回退 |
| `chapters` | list[str] | 涉及的章节标题(含 `(第i/n段)` 后缀,如果是拆出来的) |
| `in_target_range` | bool | 是否落在 [target_min, target_max] |
| `filename` | str | 对应的 .txt 文件名 |

### 5.3 `library/{书名}/meta.json`

| 字段 | 说明 |
|---|---|
| `title` | 自动取 .txt 文件名(去后缀) |
| `source_file` | 原文件绝对路径 |
| `ingested_at` | ISO 时间戳 |
| `total_chars` | 全书总字数(non-whitespace) |
| `n_chunks` | 块总数 |
| `n_chapters_detected` | 检测到的不重复章节数 |
| `n_chunks_from_chapter_split` | 来自超长章拆分的块数 |
| `target_min` / `target_max` | 当次运行的目标区间 |

### 5.4 `library/{书名}/原文/{原文件名}`
原 .txt 文件的副本,做保险。

## 6. 何时需要人工干预

- **大量块 > 15000**:说明边界识别失效,可能是这本书的章节格式特殊。打开几个块看一下,告知用户。
- **大量块 < 8000**:说明书章节本身就很短(常见于网文)。可以接受。
- **检测章节数远少于实际**:说明章节标题用了非常规格式(比如纯数字,或 `「第一章」` 带引号)。建议告诉用户并问要不要补充正则。
- **`no_chapter` 占多数**:整本书没有章节标记。让用户确认是不是短篇集或散文,如确认就这样。

## 7. 常见参数调整

```bash
# 默认 10000-15000
python split_novel.py --input book.txt

# 调小目标(适合摘要更细致,但调用次数更多)
python split_novel.py --input book.txt --min 6000 --max 10000

# 调大目标(适合长章节小说,牺牲一点细致度换更少块数)
python split_novel.py --input book.txt --min 12000 --max 18000

# 自定义输出位置
python split_novel.py --input book.txt --output ./my_novels
```
