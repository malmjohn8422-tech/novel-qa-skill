# 设计决策

- **切块用脚本不用模型**:切块是确定性操作,必须 byte-exact 保留原文,不能丢字。
- **块大小 10000-15000**:上限保证摘要模型读得细,下限避免摘要信息密度过低。
- **按章而非按字硬切**:章节是作者设定的完整单元,只有超长章才章内拆。
- **重切默认不覆盖**:重切会使旧 `summary.json`、角色档案和高层文档失效,必须显式 `--force`。
- **回答带块号**:让用户能直接验证答案来源。
- **主线程只传路径**:正文和全量摘要留在文件系统,worker 自行读写,减少 main thread 上下文消耗。
- **问答先跑检索脚本**:脚本只返回块号和短 snippet,比直接读多个 summary/全文更省 token。
- **keywords/aliases 可选**:兼容旧库,新库检索更准。
- **长篇用分段聚合**:超长小说的全量摘要缓存也会变大,分段摘要把高层文档输入压缩到稳定规模。
