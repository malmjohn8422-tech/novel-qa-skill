# 回答输出规范

回答用户关于已入库小说的问题时,**严格按本文档输出**。核心原则:**可验证、不编造、长度匹配问题**。

---

## 1. 块号引用(强制)

每个事实性论断**必须**带块号引用,让用户能直接 `cat chunks/NNN.txt` 验证。

### 1.1 格式

| 情况 | 格式 |
|---|---|
| 单块来源 | `[块 042]` |
| 多块来源 | `[块 012, 018, 025]` |
| 连续块 | `[块 012-015]` |
| 高级文档来源 | `[档案: 概要.md]` 或 `[档案: 角色/罗辑.md]` |
| 混合(高级文档 + 块) | `[档案: 故事线.md; 块 18]` |

### 1.2 块号写在句尾

```
✓ 罗辑在度假别墅醒来 [块 012]。
✓ 庄颜在两人结婚后告知罗辑联合国的特别会议 [块 012, 018]。
✗ 罗辑[块012]在度假别墅[块012]醒来[块012]。   ← 过度标注,干扰阅读
```

### 1.3 不能没有引用的情况

| 内容 | 是否要引用 |
|---|---|
| 具体事件、对话、动作、外貌描写 | **要** |
| 角色性格判断("罗辑性格冷静") | 要(基于哪几块得出的) |
| 全书总评、阅读建议、风格归纳 | 可不要,但**说清是评价而非原文** |
| 用户问"你怎么看" | 可不要,坦白这是你的判断 |

## 2. 不编造

### 2.1 找不到就说找不到

```
✓ "原文未涉及罗辑的童年。"
✓ "在已入库的 90 块里没有提到这个细节。"
✗ "想必罗辑童年应该是……"      ← 编造
✗ "通常面壁者都有……"          ← 用泛化代替原文
```

### 2.2 不要伪造块号

如果不确定某句出自哪块,**重新走一次检索**(见 [qa_routing.md](qa_routing.md))再下笔。**绝不能**:

```
✗ "罗辑曾被史强威胁过 [块 045]"    ← 块 045 实际没这内容
```

宁可不带引用、说"在某一块附近出现过,具体待查"。

### 2.3 区分原文事实 vs 你的推断

```
✓ "罗辑表面冷漠 [块 012, 018],但对庄颜流露温情 [块 025] —— 这种张力构成他的核心矛盾(此处为推断,原文未明说)。"
```

## 3. 长度匹配问题

| 问题大小 | 答案长度 |
|---|---|
| "庄颜什么时候第一次出场" | 1-2 句话 + 块号 |
| "庄颜是怎样的人" | 1-2 段 (~200-400 字) |
| "整本书讲了什么" | 4-8 段 (~800-1500 字),用 `##` 二级标题分段 |
| "刹车被破坏这条线怎么演进的" | 时间线式分点,3-6 个节点 + 每个的块号 |

**反例**:用户问"庄颜是谁",你写 2000 字。是浪费用户时间。

---

## 4. 引用原文

### 4.1 引用条件

- 用户**明确要求**"原文/原话/逐字"——必须引用,不改写
- 用户问"她说了什么"——可以引用关键句,加块号
- 一般情况——**不**直接引用,用自己的话概括即可

### 4.2 引用格式

```
> "你的妻子,当场就走了。"  —— 陈守义 [块 001]
```

或

```
陈守义对林川说"你的妻子,当场就走了" [块 001]。
```

### 4.3 不许擅自缩减或改写原文

引用必须 byte-exact。改了用户验证时会发现,信任坍塌。

byte-exact 包括原文中的**所有用词**:身体描写、动作词、对话用语、半隐喻或显性词汇,一律保留不替换、不省略、不加省略号。不在引用中插入"……"或"[此处略]"之类。

`search_novel.py search --source text` 返回的 snippet 只用于定位块号。正式引用前必须 Read 对应 `chunks/NNN.txt`,从原文块里复制确认后的 byte-exact 片段。

## 5. 各类问题的答案模板

### 5.1 整体走向

```markdown
《{书名}》主要讲述 [一句话核心矛盾] [档案: 概要.md]。

## 起点
[原始处境,用块号支撑]

## 发展
[核心冲突 + 主要转折,每个带块号]

## 结局
[结尾状态;若未覆盖完整结局就说明]
```

### 5.2 角色分析

```markdown
**{角色名}** 的核心特点是 [3-5 个词] [档案: 角色/{name}.md]。

[一段 200 字左右的弧光/性格说明,引用 2-4 个关键块]

**关键事件**:
- [块 N1] {事件}
- [块 N2] {事件}
```

### 5.3 章节情节

```markdown
**{章节标题}**(块 NN):

[3-5 句概括本章发生的事]

主要角色:{列出};地点:{列出}。

[如用户问得更深,补充关键对话/细节,带块号]
```

### 5.4 具体细节(衣着、神态、对话)

```markdown
{问题里的角色/场景}的{细节}:

[直接陈述细节,引用具体块] [块 N]。

(原文摘录,如能引出来:`"..."` [块 N])
```

### 5.5 原文引用

```markdown
原文 [块 NN] 中相关段落:

> [byte-exact 引用,允许保留原文换行]

[简短的上下文解释,可选]
```

### 5.6 找不到信息

```markdown
关于 {问题},在已入库的 {N} 块中**没有找到**直接描写。

可能的相关内容:
- [块 X] 提到了 {间接信息}
- [块 Y] 出现过 {人/物},但没展开

如果你确认原文有这个内容,可能需要重新跑 Stage 1(某块摘要可能漏了)。
```

## 6. 多本小说时的处理

如果 `./library/` 下有多本书:

**开头一句话表态**:

```
基于《{slug}》回答:

[正文……]
```

如果用户问的内容**明显跨书**(比如他问的是另一本里的角色),先停下来确认:

```
你说的 {角色名/事件} 是哪本书的?目前 library 里有:
- 《X》
- 《Y》
- 《Z》

请指明,或我默认用最近入库的《X》回答。
```

---

## 7. 不要做的事

| 错误 | 为什么不要 |
|---|---|
| 在答案末尾加"以上仅供参考" | 没意义。该自信就自信,该说不知道就说不知道 |
| 用 emoji 加强语气 | 用户没要求,显得不严肃 |
| 把答案分得很碎(每点一行,大量空行) | 适合的就用段落,不适合的就用列表,别用空白填长度 |
| 复述用户的问题再回答 | 浪费 token |
| 在角色分析里加"我们可以学到……" | 这不是读后感,是检索回答 |
| 引用块号但块号位置不对 | 用户去 `chunks/NNN.txt` 验证查不到,信任坍塌 |
