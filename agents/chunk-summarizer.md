# chunk-summarizer worker prompt

这个文件是 Stage 1 worker agent 的执行模板。Main thread 只传任务路径,不要传小说正文。

## 输入

你会收到一个任务对象或等价文字,至少包含:

- `slug`: 小说标识
- `chunk`: 块号,如 `17`
- `chunk_path`: `library/{slug}/chunks/017.txt`
- `meta_path`: `library/{slug}/chunks/017.meta.json`
- `output_path`: `library/{slug}/chunks/017.summary.json`

## 任务

读取 `meta_path` 和 `chunk_path`,为这一块中文小说生成摘要 JSON,并直接写入 `output_path`。不要把小说正文或完整 JSON 回传给 main thread。

## 输出文件 schema

```json
{
  "summary": "...",
  "characters": ["...", "..."],
  "locations": ["..."],
  "key_events": ["...", "..."],
  "keywords": ["...", "..."]
}
```

前四个字段必须存在。`keywords` 为可选但强烈建议输出,旧库没有该字段也有效。

## 字段规则

### `summary`

- 180-220 字中文叙述
- 第三人称陈述,只写发生了什么,不评价、不抒情
- 覆盖本块的主要事件、参与者、转折/结局
- 不引用原文长句,用自己的话概括
- 不写"本块讲了"、"这一段描述了"之类开场
- 涉及性爱/亲密场景时,如实保留事件(谁、和谁、做了什么),使用中性叙述词(临幸/交合/亲密接触),不省略事件

### `characters`

只列同时满足以下条件的角色:

1. 有名字或唯一固定称呼
2. 在本块中有对话、动作或被详细描写

不要列代词、泛称、仅被提到的人名。宁可多列有实际行动的角色,不要漏掉后续可能用于细节问答的人物。

### `locations`

- 2-5 个主要场景
- 尽量具体,如"罗辑的别墅"优先于"室内"
- 同一物理地点不同时间状态不必拆分

### `key_events`

- 1-3 条最重要情节点
- 每条 1-2 句话
- 按时间顺序排列
- 聚焦动作、转折、揭示,不要只写心理或环境描写

### `keywords`

- 8-20 个中文检索词
- 包含本块的关键人物、物品、地点、组织、能力/设定、特殊事件词
- 优先选择用户后续可能会问到的细节词,如"录音笔"、"刹车被破坏"、"茶馆老板"
- 不要放太泛的词,如"故事"、"事情"、"人物"

## 写入要求

- 使用 UTF-8 写入 `output_path`
- JSON 必须可被 `json.loads()` 解析
- 保持 `ensure_ascii=False` 风格,不要 markdown 围栏
- **字符串内引用专有名词时**,使用中文引号 `「」` 或全角 `""` 或单引号 `'`,**严禁使用未转义的 ASCII 双引号 `"`**。例如写 `悟出「澧水证道」的秘密` 而不是 `悟出"澧水证道"的秘密` — 后者会让 JSON parser 提前结束字符串导致解析失败
- 写完后不要在回复里粘贴 JSON

## 最终回复

只回复一行短状态:

- 成功: `OK chunk=017`
- 失败: `FAILED chunk=017 reason=简短原因`
